  <name>Task 1: Clone NextGCore and nextgsim, start stack with Podman, test NWDAF endpoint</name>
  <files>.planning/phases/01-backend-infrastructure/01-02-SUMMARY.md</files>
  <read_first>

  </read_first>
  <action>
    Per D-12, validate NextGCore locally with Podman before any OpenShift work.

    Step 1 -- Enable Podman Docker-compatible socket. On macOS with Podman Desktop, the socket is typically already available. Verify with: podman info --format '{{.Host.RemoteSocket.Path}}'.

    Step 2 -- Clone both repos into a temporary location:
    git clone https://github.com/NextgCoreLab/nextgcore.git /tmp/nextgcore
    git clone https://github.com/NextgCoreLab/nextgsim.git /tmp/nextgsim

    Step 3 -- Inspect the docker-compose.yml at /tmp/nextgcore/docker/rust/docker-compose.yml. Note the network configuration (172.23.0.0/24 subnet), NF container names, and NWDAF port. Also inspect /tmp/nextgcore/k8s/ directory to assess whether existing k8s manifests are usable for OpenShift porting (Assumption A1 from RESEARCH.md).

    Step 4 -- Start the full 22-NF stack. Use docker-compose binary (v5.0.2) against Podman socket -- NOT podman-compose (per RESEARCH.md Pitfall 3, podman-compose breaks NextGCore's custom bridge networking). Set DOCKER_HOST to the Podman socket path. Run from /tmp/nextgcore/docker/rust/:
    docker-compose -f docker-compose.yml up -d

    Step 5 -- Wait for NFs to start (allow ~30-60 seconds). Check nextgsim logs for UE registration success (per D-13):
    docker-compose logs nextgsim-ue 2>&1 | grep -E "UE is now REGISTERED|is now ACTIVE"
    Expected: "Registration Accept: UE is now REGISTERED" and "PDU session 1 is now ACTIVE"

    Step 6 -- Test NWDAF analytics endpoint (the critical validation). From within the docker network, curl the NWDAF analytics endpoint:
    docker-compose exec nextgcore-amf curl -s http://nextgcore-nwdaf:8080/nnwdaf-analyticsinfo/v1/analytics?event-id=LOAD_LEVEL_INFORMATION

    Also try ABNORMAL_BEHAVIOUR event type. Note the actual endpoint path if it differs from the assumed path (RESEARCH.md Assumption A4).

    Step 7 -- Record results. If NWDAF responds with actual analytics data (HTTP 2xx, non-empty JSON body with analytics fields), record as GO. If NWDAF returns errors, empty results, or the endpoint does not exist, record as NO-GO.

    Step 8 -- Clean up: docker-compose down -v (from /tmp/nextgcore/docker/rust/).

    Timebox per D-11: Use your judgment on how long to spend debugging if initial attempts fail. If NextGCore images fail to pull or build, or if NFs fail to start, do not spend excessive time -- the fallback (Prism NWDAF mock) is acceptable.
  </action>
