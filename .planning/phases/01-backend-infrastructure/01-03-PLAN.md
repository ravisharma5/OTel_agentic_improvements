<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> OpenShift cluster | oc CLI authenticated with cluster-admin token |
| External client -> Prism services | Mock API responses accessible within cluster |
| Podman -> OpenShift internal registry | Container images pushed from local build to cluster |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Prism mock endpoints | mitigate | All Services are ClusterIP (no Routes); mock data is not sensitive (schema-generated, no PII); endpoints only accessible within the cluster network |
| T-03-02 | Elevation of Privilege | Prism containers | mitigate | Prism runs as a standard Node.js process; containers run under default restricted-v2 SCC; no elevated capabilities requested; no host access |
| T-03-03 | Spoofing | oc CLI credentials | accept | Developer authenticates with personal token; token scope limited to personal/dev cluster (D-01); not a shared/production cluster |
| T-03-04 | Tampering | Prism container images in internal registry | accept | Images built locally from vendored specs + official Prism base image; internal registry requires authentication; dev-only cluster |
| T-03-SC | Tampering | Prism base image pull | mitigate | stoplight/prism:5 verified in Package Legitimacy Audit (10M+ pulls, 7-year history); image digest can be pinned for additional assurance |
</threat_model>
