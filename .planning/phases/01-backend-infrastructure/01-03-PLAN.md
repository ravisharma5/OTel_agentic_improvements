    - prism-tmf642.yaml: name prism-tmf642, spec file tmf642_alarm_v5.0.1.oas.yaml. Readiness and liveness probes use httpGet with path /alarm on port 4010. This is a valid GET list endpoint in the TMF642 spec.
    - prism-tmf628.yaml: name prism-tmf628, spec file tmf628_performance_v4.0.0.swagger.json. Per D-07, mock Swagger 2.0 as-is. Per RESEARCH.md Pitfall 5, test this spec locally with Prism before deploying. Readiness and liveness probes use httpGet with path /measurementCollectionJob on port 4010.
    - prism-tmf621.yaml: name prism-tmf621, spec file tmf621_troubleticket_v5.0.1.oas.yaml. Readiness and liveness probes use httpGet with path /troubleTicket on port 4010.
    - prism-camara.yaml: name prism-camara, spec file camara_location_verification.yaml. CAMARA location verification is POST-heavy with no safe GET endpoints. Readiness and liveness probes use tcpSocket on port 4010 instead of httpGet, to avoid HTTP 4xx/405 errors that would cause crash-looping.
    - prism-camara-retrieval.yaml: name prism-camara-retrieval, spec file camara_location_retrieval.yaml. Same tcpSocket probe pattern as prism-camara (POST-heavy API, no safe GET endpoint).

    Readiness probe: initialDelaySeconds 5, periodSeconds 10.
    Liveness probe: initialDelaySeconds 10, periodSeconds 30.

    b. Push to cluster registry: podman push {registry_route}/otel25-backends/prism-{api}:latest

    To get the registry route: oc get route default-route -n openshift-image-registry -o jsonpath='{.spec.host}'. If no external route exists, expose it: oc patch configs.imageregistry.operator.openshift.io/cluster --type merge -p '{"spec":{"defaultRoute":true}}'.

    Log in to the registry: podman login -u $(oc whoami) -p $(oc whoami -t) {registry_route} --tls-verify=false

    Registry push fallback (addresses review concern: internal registry operationally brittle): If the internal registry route/push fails (e.g., missing default route, DNS resolution issues, TLS certificate errors even with --tls-verify=false), use a personal public registry namespace as fallback:

    b. Log in to public registry: podman login quay.io (or docker.io)
    c. Push: podman push quay.io/{username}/prism-{api}:latest
    d. Update the Deployment manifests to reference the public registry image path instead of the internal registry
    Document which registry was used in the SUMMARY so Plan 04 knows the image source.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer machine -> OpenShift cluster | oc CLI authenticated with cluster-admin token |
| External client -> Prism services | Mock API responses accessible within cluster |
| Podman -> image registry | Container images pushed from local build to internal or public registry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Prism mock endpoints | mitigate | All Services are ClusterIP (no Routes); mock data is not sensitive (schema-generated, no PII); endpoints only accessible within the cluster network |
| T-03-02 | Elevation of Privilege | Prism containers | mitigate | Prism runs as a standard Node.js process; containers run under default restricted-v2 SCC; no elevated capabilities requested; no host access |
| T-03-03 | Spoofing | oc CLI credentials | accept | Developer authenticates with personal token; token scope limited to personal/dev cluster (D-01); not a shared/production cluster |
| T-03-04 | Tampering | Prism container images in registry | accept | Images built locally from vendored specs + official Prism base image; internal registry requires authentication; if public registry used as fallback, images are pushed by authenticated user to personal namespace |
| T-03-SC | Tampering | Prism base image pull | mitigate | stoplight/prism:5 verified in Package Legitimacy Audit (10M+ pulls, 7-year history); image digest can be pinned for additional assurance |
</threat_model>
