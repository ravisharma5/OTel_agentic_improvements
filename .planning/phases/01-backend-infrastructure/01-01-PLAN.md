    Create backends/prism/Dockerfile -- a parameterized Dockerfile that accepts SPEC_FILE as a build arg. Base image is stoplight/prism:5. The Dockerfile COPYs the spec file specified by SPEC_FILE into /specs/api.yaml inside the container. Set NODE_ENV=production (per RESEARCH.md anti-pattern: processing logs slow Prism without it). Use ENTRYPOINT ["node", "dist/index.js"] and CMD ["mock", "-h", "0.0.0.0", "-p", "4010", "--dynamic", "/specs/api.yaml"]. The -h 0.0.0.0 is mandatory (per D-08 and RESEARCH.md anti-pattern: Prism defaults to localhost which is unreachable from outside container). The --dynamic flag generates varied responses from schema (per D-08).

    Build context for this Dockerfile is the backends/ directory. Build command pattern: podman build --build-arg SPEC_FILE=specs/tmf642_alarm_v5.0.1.oas.yaml -f prism/Dockerfile -t prism-tmf642 backends/

    Create backends/scripts/validate-mocks.sh -- per D-09 and RESEARCH.md "Schema Validation Strategy", use a standalone validation script (NOT Prism validation-proxy, which would be circular). The script curls each of the 4 Prism mock endpoints with Prefer: dynamic=true header, checks for HTTP 2xx responses, validates response bodies are parseable JSON, and reports PASS/FAIL per endpoint. Endpoints array:
    - tmf642|$TMF642_URL|/alarm|GET
    - tmf628|$TMF628_URL|/measurementCollectionJob|GET
    - tmf621|$TMF621_URL|/troubleTicket|GET
    - camara|$CAMARA_URL|/verify|POST

    The script should accept base URLs via environment variables (TMF642_URL, TMF628_URL, TMF621_URL, CAMARA_URL) with defaults pointing to in-cluster Service DNS names (e.g., http://prism-tmf642.otel25-backends.svc.cluster.local:4010). Exit 0 on all pass, exit 1 on any failure.

    Create backends/scripts/verify-routing.sh -- per D-16, reads the backend-routing ConfigMap from OpenShift using oc, curls each URL from the ConfigMap, verifies 2xx responses. Then demonstrates the switching contract: patches one ConfigMap key (TMF642_BASE_URL) to a known-bad URL, re-reads, confirms it now points to the new value. Patches it back to the original value. Uses NAMESPACE variable defaulting to otel25-backends and CM_NAME defaulting to backend-routing.

    Create backends/scripts/check-nwdaf.sh -- per RESEARCH.md NWDAF validation patterns. Curls the NWDAF analytics endpoint at $NWDAF_BASE_URL/nnwdaf-analyticsinfo/v1/analytics?event-id=LOAD_LEVEL_INFORMATION. Checks for HTTP 2xx response and non-empty JSON body. NWDAF_BASE_URL defaults to http://nextgcore-nwdaf.otel25-backends.svc.cluster.local:8080. Uses one-shot analytics queries, not subscriptions (per RESEARCH.md Pitfall 2: subscriptions are memory-only, lost on restart).

    All scripts use #!/usr/bin/env bash and set -euo pipefail. Make all scripts executable with chmod +x.
  </action>
