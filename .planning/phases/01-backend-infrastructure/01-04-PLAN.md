## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External client -> NWDAF service | Analytics queries to NextGCore or Prism NWDAF mock |
| ConfigMap -> Pod env vars | Future MCP servers will read ConfigMap URLs to route requests |
| UPF container -> host kernel | NET_ADMIN capability for TUN/TAP (NextGCore path only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | NextGCore UPF container | mitigate | Custom SCC grants only NET_ADMIN + NET_RAW (not privileged); dedicated ServiceAccount nextgcore-upf; SCC never modifies OpenShift defaults; only applies if go-nextgcore path is taken |
| T-04-02 | Information Disclosure | NWDAF analytics endpoint (no auth) | accept | Internal-only ClusterIP Service; dev cluster (D-01); no PII in analytics data; acceptable for Phase 1 mock/sandbox use. Revisit auth if endpoints are exposed via Route |
| T-04-03 | Denial of Service | Stale ConfigMap URLs pointing to non-existent services | mitigate | verify-routing.sh validates all 5 URLs return HTTP 2xx before Phase 1 is marked complete; D-16 switching test proves ConfigMap reads reflect current values |
| T-04-04 | Denial of Service | NWDAF subscription loss on pod restart (issue #192) | accept | Known NextGCore limitation; Phase 1 uses one-shot analytics queries (not subscriptions); documented in SUMMARY for downstream phases |
| T-04-05 | Spoofing | ConfigMap values (no integrity check) | accept | ConfigMap is cluster-internal, editable only by authenticated oc users; dev cluster with admin access (D-01, D-03); no ConfigMap admission webhook needed for Phase 1 |
| T-04-SC | Tampering | NextGCore container images | accept | Images built from source (git clone verified in Plan 02); AGPL-3.0 sandbox use per PROJECT.md; dev-only cluster |
</threat_model>
