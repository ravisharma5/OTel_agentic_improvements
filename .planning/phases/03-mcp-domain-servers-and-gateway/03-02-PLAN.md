<objective>
Build the three single-spec TMF domain MCP servers (TMF642 alarm management, TMF628 performance, TMF621 trouble ticket) totaling 15 tools, using Phase 2's conversion CLI for scaffold generation and hand-curating each for production readiness.

Purpose: These 15 tools represent 75% of the new domain tools (15 of 20). TMF642 is the most complex (PATCH /alarm/{id} must be split into 3 distinct acknowledge/clear/comment tools). TMF628 and TMF621 are straightforward from_openapi() scaffolds.

Output: Three complete domain server directories (mcp/tmf642, mcp/tmf628, mcp/tmf621) each with server.py, allowlist, spec copy, Dockerfile, and pyproject.toml.

**Scope note:** This plan touches 16 files across 2 tasks (5 files x 3 domains + 1 shared CLI edit). This exceeds the 15-file soft threshold but is kept as one plan because: (a) TMF628 and TMF621 are near-identical copies of TMF642's pattern minus the PATCH splitting -- splitting them into a separate plan adds renumbering churn across all 6 plans and ROADMAP.md with no quality benefit, (b) all three servers are independent within the plan (no intra-plan dependencies), and (c) both tasks have focused verification steps that catch failures early.
</objective>

| T-03-SC | Tampering | pip/uv package installs | mitigate | blocking-human checkpoint in Plan 01 for all [ASSUMED] packages |
</threat_model>
