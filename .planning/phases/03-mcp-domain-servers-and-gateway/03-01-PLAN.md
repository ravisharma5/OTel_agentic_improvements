  <name>Task 2: Create verification scripts</name>
  <files>scripts/verify-domain-tools.sh, scripts/verify-gateway.sh</files>
  <read_first>
    - scripts/verify-mcp-telecom.sh (analog -- session management, SSE parsing, JSON-RPC assertions)

    - .planning/phases/03-mcp-domain-servers-and-gateway/03-RESEARCH.md (Example 3 -- gateway curl patterns, session ID extraction)
  </read_first>
  <action>
    Create two parameterized verification scripts following the session-management and SSE-parsing patterns established in scripts/verify-mcp-telecom.sh.

    **scripts/verify-domain-tools.sh:**
    - Accept domain name as $1 (tmf642, tmf628, tmf621, nwdaf, camara)
    - Accept optional base URL as $2 (default: http://localhost:8000)
    - Define expected tool counts per domain in an associative array: tmf642=6, tmf628=5, tmf621=4, nwdaf=3, camara=2
    - Perform MCP session initialization (POST /mcp with initialize method, capture Mcp-Session-Id from response headers, send notifications/initialized)
    - Test 1 (smoke): Send tools/list, verify tool count matches expected count for the domain
    - Test 2 (integration): For each discovered tool, send tools/call with minimal valid arguments (can use empty object {}), verify HTTP 200 and valid JSON-RPC response (tool may return error content from Prism -- that is acceptable; the test verifies MCP protocol round-trip, not response semantics)
    - Print PASS/FAIL summary with tool names and counts
    - Exit 0 on all pass, exit 1 on any failure
    - Include _parse_sse_json helper for SSE response parsing (same pattern as verify-mcp-telecom.sh)

    **scripts/verify-gateway.sh:**
    - Accept mode as $1: initialize, tools-list, virtual-tmf, tool-call
    - Accept gateway URL as $2 (default: http://mcp.apps.cluster-domain/mcp)
    - Accept optional JWT token as $3 (for authenticated requests, added as Authorization: Bearer header)
    - Mode "initialize": POST /mcp with initialize method, verify valid JSON-RPC response with serverInfo
    - Mode "tools-list": Initialize session, send tools/list, verify tool count >= 78 (20 domain + 58 MCP-Telecom), print all tool names
    - Mode "virtual-tmf": Initialize session, send tools/list with X-Mcp-Virtualserver: otel25-gateway/tmf-tools header, verify exactly 15 tools returned (6+5+4 TMF tools)
    - Mode "tool-call": Initialize session, invoke one tool (e.g., tmf642_listAlarm or first discovered tool), verify valid JSON-RPC response
    - Include session management (initialize handshake, Mcp-Session-Id header for all requests)
    - Include SSE response parsing
    - Print PASS/FAIL per test
    - Exit 0/1 appropriately

    Both scripts must be executable (chmod +x). Use bash, not sh, for associative arrays.
  </action>
  <verify>
    <automated>bash -n scripts/verify-domain-tools.sh && bash -n scripts/verify-gateway.sh && test -x scripts/verify-domain-tools.sh && test -x scripts/verify-gateway.sh && echo "PASS: both scripts parse and are executable"</automated>
  </verify>
