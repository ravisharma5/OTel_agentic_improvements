<objective>
Provision the RHCL MCP Gateway infrastructure on OpenShift from scratch: OpenShift Service Mesh 3.3+, cert-manager, Keycloak for authentication, and the RHCL MCP Gateway Operator with Gateway and MCPGatewayExtension objects.

Purpose: Per D-04, all gateway infrastructure is provisioned in Phase 3. This is the foundation that Plans 05 and 06 build upon -- without a ready gateway, no backend registration or end-to-end verification can proceed. The OCP version check is the critical gating first step (Pitfall 1).

Output: All gateway prerequisite operators installed, Istio control plane ready, Gateway + MCPGatewayExtension deployed and Ready in otel25-gateway namespace, Keycloak instance running for auth (D-08).
</objective>

  <action>
    **CRITICAL GATING STEP: Verify OCP cluster version.**
    Run: oc version
    The server version MUST be 4.19 or later. If the server version is 4.18.x or earlier, STOP and report to user: "OCP cluster is version X.Y -- RHCL 1.4 requires 4.19+. Options: (1) upgrade cluster to 4.19+, (2) use RHCL 1.3 with OSSM 3.2 (contradicts D-02, needs user approval)." Do NOT proceed with operator installations if version is below 4.19.

    **Step 1: Create gateway namespace.**
    Create gateway/openshift/namespace.yaml for otel25-gateway namespace with labels purpose: phase-3-gateway, layer: gateway. Following the pattern from mcp/openshift/namespace.yaml (purpose label pattern) and backends/openshift/namespace.yaml.
    Apply: oc apply -f gateway/openshift/namespace.yaml

    **Step 2: Install OSSM 3.3+ Operator.**
    Create gateway/openshift/ossm-subscription.yaml:
    - apiVersion: operators.coreos.com/v1alpha1, kind: Subscription
    - metadata.name: servicemeshoperator3, namespace: openshift-operators
    - spec.channel: stable, spec.name: servicemeshoperator3, spec.source: redhat-operators, spec.sourceNamespace: openshift-marketplace, spec.installPlanApproval: Automatic
    Apply: oc apply -f gateway/openshift/ossm-subscription.yaml
    Wait: oc wait --for=condition=CatalogSourcesUnhealthy=False subscription/servicemeshoperator3 -n openshift-operators --timeout=120s (or poll until CSV is Succeeded)

    **Step 3: Create IstioCNI.**
    Create gateway/openshift/istio-cni.yaml with:
    - Namespace istio-cni
    - IstioCNI CR (apiVersion: sailoperator.io/v1, kind: IstioCNI, name: default, spec.namespace: istio-cni, spec.profile: openshift)
    Apply: oc apply -f gateway/openshift/istio-cni.yaml
    Wait: oc wait --for=condition=Ready istiocni/default --timeout=120s

    **Step 4: Create Istio control plane.**
    Create gateway/openshift/istio.yaml with:
    - Namespace istio-system with label istio-discovery: default
    - Istio CR (apiVersion: sailoperator.io/v1, kind: Istio, name: default, namespace: istio-system, spec.namespace: istio-system, spec.updateStrategy.type: InPlace)
    Apply: oc apply -f gateway/openshift/istio.yaml
    Wait: oc wait --for=condition=Ready istio/default -n istio-system --timeout=180s

    **Step 5: Install cert-manager Operator.**
    Create gateway/openshift/cert-manager-subscription.yaml:
    - Subscription in openshift-cert-manager-operator namespace (or openshift-operators)
    - spec.channel: stable, spec.name: openshift-cert-manager-operator, spec.source: redhat-operators
    Apply: oc apply -f gateway/openshift/cert-manager-subscription.yaml
    Wait for CSV to reach Succeeded phase.

    **Step 6: Install Keycloak Operator + instance.**
    Create gateway/openshift/keycloak-subscription.yaml:
    - Subscription for rhbk-operator (Red Hat build of Keycloak) in otel25-gateway namespace
    - spec.channel: stable-v26, spec.name: rhbk-operator, spec.source: redhat-operators
    - Include OperatorGroup targeting otel25-gateway namespace
    Apply: oc apply -f gateway/openshift/keycloak-subscription.yaml
    Wait for Keycloak Operator CSV to reach Succeeded.

    Create gateway/openshift/keycloak.yaml:
    - Keycloak CR in otel25-gateway namespace
    - Minimal configuration: hostname pointing to keycloak route, ephemeral PostgreSQL (sufficient for WG training pipeline -- not production)
    - spec.instances: 1
    Apply: oc apply -f gateway/openshift/keycloak.yaml
    Wait: oc wait --for=condition=Ready keycloak/mcp-keycloak -n otel25-gateway --timeout=300s

    **Step 7: Configure Keycloak realm and client via admin API.**
    After Keycloak is ready:
    - Get Keycloak admin credentials: oc get secret mcp-keycloak-initial-admin -n otel25-gateway -o jsonpath='{.data.username}' | base64 -d; oc get secret mcp-keycloak-initial-admin -n otel25-gateway -o jsonpath='{.data.password}' | base64 -d
    - Get Keycloak route: oc get route mcp-keycloak -n otel25-gateway -o jsonpath='{.spec.host}'
    - Via admin REST API or oc exec + curl:
      a) Create realm "mcp"
      b) Create client "mcp-gateway" with client authentication enabled (confidential)
      c) Create a test user "mcp-agent" with a password
      d) Create client roles: "tool-access" (basic role for tool invocation)
    - Test token retrieval: curl -X POST https://<keycloak>/realms/mcp/protocol/openid-connect/token -d "grant_type=password&client_id=mcp-gateway&client_secret=<secret>&username=mcp-agent&password=<password>"
  </action>

<task type="auto">

  <action>
    **Step 1: Install RHCL MCP Gateway Operator.**
    Create gateway/openshift/mcp-gateway-subscription.yaml with:
    - OperatorGroup (apiVersion: operators.coreos.com/v1, kind: OperatorGroup, name: mcp-gateway-og, namespace: otel25-gateway, spec.targetNamespaces: [otel25-gateway])
    - Subscription (apiVersion: operators.coreos.com/v1alpha1, kind: Subscription, name: mcp-gateway, namespace: otel25-gateway, spec.channel: preview, spec.name: mcp-gateway, spec.source: redhat-operators, spec.sourceNamespace: openshift-marketplace)
    Apply: oc apply -f gateway/openshift/mcp-gateway-subscription.yaml
    Wait: Poll until CSV shows version 1.4.1 or later and phase Succeeded. If only 1.4.0 is available, STOP and report: "Only RHCL 1.4.0 available -- D-02 requires 1.4.1+ due to known bugs (auth failures, instability, memory pressure). Options: (1) wait for 1.4.1 to appear in catalog, (2) proceed with 1.4.0 at user's risk."

    **Step 2: Create Gateway object.**
    Create gateway/openshift/gateway.yaml:
    - apiVersion: gateway.networking.k8s.io/v1, kind: Gateway
    - metadata.name: mcp-gateway, namespace: otel25-gateway
    - spec.gatewayClassName: openshift-default (the default GatewayClass on OCP 4.19+)
    - spec.listeners: one listener named "mcp", port 8080, protocol HTTP
    - hostname: determine the cluster's apps domain by running: oc get ingresses.config cluster -o jsonpath='{.spec.domain}' and use "mcp.<apps-domain>" as the hostname
    Apply: oc apply -f gateway/openshift/gateway.yaml
    Wait: oc wait --for=condition=Programmed gateway/mcp-gateway -n otel25-gateway --timeout=120s

    **Step 3: Create MCPGatewayExtension.**
    Create gateway/openshift/mcp-gateway-extension.yaml:
    - apiVersion: mcp.kuadrant.io/v1alpha1, kind: MCPGatewayExtension
    - metadata.name: mcp-gateway-ext, namespace: otel25-gateway
    - spec.targetRef: group gateway.networking.k8s.io, kind Gateway, name mcp-gateway, sectionName mcp
    - spec.httpRouteManagement: Enabled (auto-creates /mcp HTTPRoute)
    Apply: oc apply -f gateway/openshift/mcp-gateway-extension.yaml
    Wait: oc wait --for=condition=Ready mcpgatewayextension/mcp-gateway-ext -n otel25-gateway --timeout=120s

    **Step 4: Verify gateway endpoint.**
    Get gateway URL: GATEWAY_URL=$(oc get gateway mcp-gateway -n otel25-gateway -o jsonpath='{.status.addresses[0].value}') or use the hostname from Gateway spec.
    Test MCP initialize: curl -s -X POST http://$GATEWAY_URL/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","id":1,"method":"initialize"}'
    Expect a valid JSON-RPC response with serverInfo (may be SSE-formatted).
  </action>
  <verify>
    <automated>oc get mcpgatewayextension mcp-gateway-ext -n otel25-gateway -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}' 2>/dev/null | grep -q "True" && echo "PASS: MCPGatewayExtension is Ready" || echo "FAIL: MCPGatewayExtension not Ready"</automated>
  </verify>
  <acceptance_criteria>

    - RHCL MCP Gateway Operator CSV version is 1.4.1+ and phase is Succeeded
    - gateway/openshift/gateway.yaml defines Gateway with listener named "mcp" on port 8080 protocol HTTP
    - Gateway hostname uses the cluster's apps domain (e.g., mcp.apps.cluster.example.com)
    - gateway/openshift/mcp-gateway-extension.yaml defines MCPGatewayExtension targeting gateway mcp-gateway sectionName mcp with httpRouteManagement Enabled
    - MCPGatewayExtension status condition Ready=True
    - curl POST to gateway /mcp with initialize method returns valid JSON-RPC response
  </acceptance_criteria>
  <done>RHCL MCP Gateway operator installed (1.4.1+), Gateway and MCPGatewayExtension are Ready, gateway endpoint responds to MCP initialize</done>

|----------|-------------|
| External client -> RHCL gateway | Untrusted MCP requests from outside the cluster |
| RHCL gateway -> Keycloak | Token validation requests |
| OperatorHub -> cluster | Operator installation from Red Hat catalog |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Exposed gateway endpoint without auth | mitigate | AuthPolicy configured in Plan 06 using Keycloak JWT (D-08); gateway is accessible but auth is enforced |
| T-03-06 | Elevation of Privilege | Token replay after revocation | accept | WG training pipeline, not production; Keycloak access token lifespan provides sufficient protection |
| T-03-SC | Tampering | OLM operator installations from redhat-operators | accept | Red Hat's redhat-operators catalog is a trusted source; operator images are signed |
</threat_model>
