    a) oc get istiocni default -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}'

    **Step 7: Create and run Keycloak configuration script.**
    Create gateway/openshift/configure-keycloak.sh -- an idempotent bash script that configures the Keycloak realm, client, user, and creates a k8s Secret for the client secret. This script must be re-runnable (e.g., after pod restart wipes ephemeral Keycloak storage) without errors.

    The script must:
    a) Accept namespace as $1 (default: otel25-gateway) and Keycloak CR name as $2 (default: mcp-keycloak)
    b) Extract admin credentials from oc get secret $KEYCLOAK-initial-admin
    c) Extract Keycloak route hostname from oc get route $KEYCLOAK
    d) Obtain admin access token from Keycloak master realm
    e) Create realm "mcp" (skip if exists, using GET check first)
    f) Create client "mcp-gateway" with client authentication enabled (confidential), direct access grants enabled (for password grant flow). Skip if exists.
    g) Retrieve the client secret from Keycloak admin API (GET /admin/realms/mcp/clients/{client-id}/client-secret)
    h) Create a test user "mcp-agent" with password "***REDACTED-PASSWORD***" and enabled=true. Skip if exists.
    i) Create or update a k8s Secret named "keycloak-client-secret-mcp-gateway" in the gateway namespace containing the client secret (key: CLIENT_SECRET) and the test user password (key: USER_PASSWORD). Use oc create secret generic --dry-run=client -o yaml | oc apply -f - for idempotency.
    j) Test token retrieval: curl the token endpoint with grant_type=password, verify a valid access_token is returned
    k) Print summary: realm, client, user, secret name, token test result

    Make the script executable (chmod +x). Run it after Keycloak is Ready:
    bash gateway/openshift/configure-keycloak.sh otel25-gateway mcp-keycloak

    **--- STAGED CHECKPOINT: Keycloak + Auth Configuration ---**
    Run these checks in sequence:
    a) oc get keycloak mcp-keycloak -n otel25-gateway -o jsonpath='{.status.conditions[?(@.type=="Ready")].status}' -- must return "True"
    b) KEYCLOAK_HOST=$(oc get route mcp-keycloak -n otel25-gateway -o jsonpath='{.spec.host}')
       CLIENT_SECRET=$(oc get secret keycloak-client-secret-mcp-gateway -n otel25-gateway -o jsonpath='{.data.CLIENT_SECRET}' | base64 -d)
       USER_PASSWORD=$(oc get secret keycloak-client-secret-mcp-gateway -n otel25-gateway -o jsonpath='{.data.USER_PASSWORD}' | base64 -d)
       TOKEN_RESPONSE=$(curl -s -X POST "https://$KEYCLOAK_HOST/realms/mcp/protocol/openid-connect/token" -d "grant_type=password&client_id=mcp-gateway&client_secret=$CLIENT_SECRET&username=mcp-agent&password=$USER_PASSWORD")
       echo "$TOKEN_RESPONSE" | jq -e '.access_token' > /dev/null
    Pass criterion: Keycloak CR Ready=True AND token endpoint returns HTTP 200 with a JSON body containing a non-null access_token field.
    If Keycloak CR FAILS: Check oc logs -l app=keycloak -n otel25-gateway. Common causes: ephemeral DB initialization failure, OCP route not auto-created by operator.
    If token fetch FAILS: Re-run configure-keycloak.sh -- the realm/client/user may not have been configured (or Keycloak pod restarted and lost ephemeral state since the script last ran).

    **Why a script instead of inline commands:** Keycloak uses ephemeral PostgreSQL storage (sufficient for this WG training pipeline). If the Keycloak pod restarts between Wave 1 (this plan) and Wave 4 (03-06, which needs the client secret), the realm/client/user config is lost. This idempotent script can be re-run to reconstruct it. The k8s Secret persists independently of Keycloak pod lifecycle.

    **IMPORTANT for downstream consumers (03-06):** The k8s Secret "keycloak-client-secret-mcp-gateway" persists across Keycloak pod restarts even when Keycloak's ephemeral Postgres is wiped clean. Therefore, Secret existence is NOT a reliable signal that Keycloak's realm/client/user configuration is intact. Downstream plans (specifically 03-06 Task 2) should attempt an actual token fetch from Keycloak's token endpoint first and only re-run this script if that token fetch fails (HTTP error or missing access_token in the response).
