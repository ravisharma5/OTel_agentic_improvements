<objective>
Build the two multi-spec domain MCP servers -- NWDAF (3 tools from 2 specs) and CAMARA (2 tools from 2 specs) -- using explicit @mcp.tool() decorators instead of from_openapi() composition, per D-10a (multi-spec domains exempt from CLI generation to avoid tool-name double-prefixing with MCPServerRegistration).

Purpose: NWDAF and CAMARA each span two OpenAPI specs. For small tool counts (3 and 2), hand-writing explicit tool functions gives full control over tool names, descriptions, and parameter schemas -- cleaner than mount() composition which would add unwanted prefixes (e.g., nwdaf_analytics_getAnalytics instead of nwdaf_get_analytics). The ConfigMap watcher and /healthz patterns from generated scaffolds are reused.

Output: Two complete domain server directories (mcp/nwdaf, mcp/camara) each with server.py using explicit @mcp.tool() decorators, allowlist configs for documentation, spec copies, Dockerfile, and pyproject.toml.
</objective>

      Description: "Query NWDAF analytics data for a specific event type. Supported event types include NF_LOAD, UE_MOBILITY, UE_COMMUNICATION, etc."
      Implementation: GET (or POST, per spec) to the analytics endpoint with event-id parameter. Examine the AnalyticsInfo spec for the exact HTTP method and path.     - subscribe_nwdaf_events(event_id: str, notification_uri: str) -> str
      Description: "Subscribe to NWDAF analytics event notifications. The notification URI receives callbacks when analytics data changes."
      Implementation: POST to the subscriptions endpoint from EventsSubscription spec. Examine spec for exact path and request body schema (NnwdafEventsSubscription).
      Uses the shared client: await client.post("/subscriptions", json={"eventSubscriptions": [{"event": event_id, ...}], "notifUri": notification_uri})

    - unsubscribe_nwdaf_events(subscription_id: str) -> str
      Description: "Unsubscribe from NWDAF analytics event notifications by subscription ID."
      Implementation: DELETE to /subscriptions/{subscription_id}. Examine EventsSubscription spec for exact path.
      Uses the shared client: await client.delete(f"/subscriptions/{subscription_id}")

    d) /healthz endpoint via Starlette Route pattern
    e) create_app() + main() with uvicorn.run()

For the AnalyticsInfo tools, the analytics path is RELATIVE to the base URL. The EventsSubscription spec has a DIFFERENT server base path (/nnwdaf-eventssubscription/v1). If the EventsSubscription spec's paths conflict with the AnalyticsInfo base URL, use a second client with a separate ConfigMap key, or handle the path joining carefully. For Prism (D-11 primary target), both specs serve at the root, so a single client works.
