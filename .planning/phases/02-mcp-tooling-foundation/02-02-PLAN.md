    OpenShift arbitrary-UID support (addresses review finding: Gemini + Cursor, HIGH/MEDIUM): OpenShift runs containers with a randomly assigned UID that belongs to the root group (GID 0). The application directory and any runtime-writable paths must be group-writable for this to work. After installing dependencies and copying files, add these permission lines BEFORE the USER directive:

    RUN chgrp -R 0 /app && chmod -R g=u /app
    RUN mkdir -p /app/.cache /app/.local && chgrp -R 0 /app/.cache /app/.local && chmod -R g=u /app/.cache /app/.local
    ENV UV_CACHE_DIR=/app/.cache/uv
    ENV PYTHONDONTWRITEBYTECODE=1

    The first line grants the root group (GID 0) ownership and matching permissions on /app so any UID in group 0 can read/write. The second line creates explicit cache directories for uv and Python, also group-writable. UV_CACHE_DIR redirects uv's cache to a writable location. PYTHONDONTWRITEBYTECODE=1 prevents __pycache__ write attempts entirely.

    Use USER 1001 instead of USER mcpuser (numeric UID is the OpenShift convention for arbitrary-UID images -- the actual UID at runtime will be different, but the Dockerfile's USER sets the default).
