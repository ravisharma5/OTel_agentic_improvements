<objective>
Build the reusable OpenAPI-to-MCP conversion CLI and validate it by generating a working FastMCP server from the CAMARA Device Location spec.

Purpose: Phase 3 needs this CLI to bootstrap 20 curated MCP tools from 5 different OpenAPI specs. The CLI generates server scaffolds with operation filtering (via YAML allowlist) and ConfigMap file-watching (for backend URL switching) baked in, so each domain server starts with BACK-03 compliance built-in rather than reimplementing it.
Output: Working conversion CLI at mcp/tooling/openapi_to_mcp.py, validated via CAMARA smoke test producing a server that starts and lists its tools, and proven via synthetic 2-operation fixture that the allowlist actually excludes non-allowlisted operations.

**Pattern deviation:** This plan uses an inline Python string template (string.Template with $var substitution) in openapi_to_mcp.py instead of the separate Jinja2 file (mcp/tooling/templates/server_template.py.j2) listed in 02-PATTERNS.md's File Classification table. This avoids adding a Jinja2 dependency and avoids the brace-escaping bug that str.format() would trigger on generated Python code containing dict literals, f-strings, and set syntax (addresses review finding: Gemini, HIGH). string.Template uses $var syntax which has zero conflict with Python's {} brace usage in generated code.
</objective>

DO NOT use Jinja2 -- avoids adding a dependency for a single template. string.Template uses $var syntax which has zero conflict with Python brace usage.
